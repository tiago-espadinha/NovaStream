# Architecture

> Keep it proportional to the project. Do not invent infrastructure that doesn't exist.

## Stack and runtime
- Language/framework: React 18 + TypeScript (Vite 5) frontend; Express 4 server (Node ESM).
- Runtime and version: Node 22 or newer (the server's `node --test` glob pattern needs Node 21+, and Node 18 and 20 are end-of-life); developed on v26.
- Package manager: npm (separate `package.json` in the root and in `server/`).
- Entry points: `src/main.tsx` (frontend), `server/src/app.js` (API), served by `server/src/index.js` locally and by `api/index.js` on Vercel.

## Boundaries
- Frontend: single-page app; `src/services/apiService.ts` is the only module that calls the API.
- API: `server/src/routes/*` (search, media detail, trending, auth, saved media, collections) under `/api`.
- Localization: UI copy lives in typed i18next catalogs (`src/i18n/locales/`, English is the source; a missing key fails `tsc`, and tests check every locale has the English keys and that components carry no literal copy). The language is the stored choice (`nova-stream:language` in `localStorage`), else the first browser language with a catalog, else English; `<html lang>` follows it. The API sends data, not English labels (`creatorRole`, a tagged `length`, null season/episode names), and the client words it. Media routes take `lang` (`en`, `pt-PT`, `es`, `fr`; anything else is English) and pass it to TMDb only; genre names stay English so `genre:` search keeps matching, and an empty translated overview falls back to English. RAWG, Last.fm and Open Library answer in English.
- External services (server-side only, keys never reach the client): TMDb (movies, TV), Open Library (books), RAWG (games), Last.fm (music), Deezer (artist photos and song and album release years, no key; matched by normalised artist and title, a song's year being that of its matched track's album, fetched once per Deezer album id and shared with album cards; each lookup capped at 1s, cached in memory for 24h per instance, and each request skipped beyond 40 per 5s so a failure leaves the Last.fm data as it is and is retried on the next search).

## Data
- Stores: `server/src/db/store.js` holds users, their saved media, and their collections behind an async API. It uses Upstash Redis over its REST API when `UPSTASH_REDIS_REST_URL`/`_TOKEN` (or `KV_REST_API_URL`/`_TOKEN`) are set: `user:<id>` holds the user JSON, `user-auth:<id>` holds its password hash and session version, and `user-email:<lowercased email>` → id is claimed with `SET NX`, so duplicate registrations fail atomically. Data writes (saved media, collections, preferences) never write the auth key, so one that read the user before a password change can't restore the old password; records from before the auth key keep their auth fields inline until their next data write moves them. A deletion racing a write cleans up the auth key it may recreate; only a network failure at that exact point can leave one behind, and reads ignore it without the record. Otherwise it uses a JSON file (`server/src/db/data.json`). Password attempts are counted separately in `server/src/db/attempts.js`: `pw-attempts:account:<lowercased email>` and `pw-attempts:ip:<ip>` keys in the same Redis, or an in-memory map without Redis. Each attempt is counted before its password is checked, with `INCR`, `EXPIRE NX` and `TTL` in one `/multi-exec` transaction, so parallel guesses can't pass the limit and the window runs from the first attempt; a correct password deletes the account key and `DECR`s the IP key. A sign-in for an email with no account still runs one bcrypt compare, against a fixed dummy hash at the same cost, so response time doesn't reveal which emails have accounts. Guest favorites and collections live in browser `localStorage`.
- Key entities and ownership: a user record owns `savedMedia` (card snapshots, at most 500) and `collections` (`{ custom, assignments, media }`: custom collections, which titles are in which collection, and a card snapshot per assigned title). Built-in collection ids are defined in `src/utils/collections.ts` and mirrored on the server for validation.
- Guest to account: on sign-in, guest favorites are uploaded and removed from the browser once the server accepts them; guest collections are merged into the account's (same-named collections combine; within an exclusive group the account's choice wins) and cleared after the merged document saves.
- Migration strategy: none yet. Records written before collections were added have no `collections` field and read as empty.

## APIs and integrations
| Route or integration | Purpose | Auth and validation | Failure behavior |
|---|---|---|---|
| `GET /api/search?q&type&musicKind&lang` | Cross-media search | Public. `q` required, ≤200 chars; `type` and `musicKind` must be known values (400 otherwise, with a user-readable message) | Each media type is searched in parallel with an 8s timeout. Failures don't fail the request: the response is `{ results, errors: [{ type, code }] }` with `code` in `not_configured`, `not_found`, `timeout`, `unavailable`. Raw provider messages are logged on the server only. |
| `GET /api/trending` | Home "Trending this week" shelf | Public. Optional `lang` | Same `{ results, errors }` contract and 8s per-type timeout as search. Up to 4 items per type, each provider's own order interleaved by type (popularity signals aren't compared across providers). Each type's list is cached in memory for 6h (films and TV per language); concurrent requests share one fetch and failures aren't cached. Sources: TMDb `trending/{movie,tv}/week`, Last.fm `chart.gettoptracks`, RAWG `games` added in the last 30 days (no trending endpoint), Open Library `trending/weekly.json` (undocumented; may change without notice). |
| `GET /api/media/:type/:id?lang` | Title detail | Public. Unknown `type` → 400 | Same codes as search, mapped to 404 (`not_found`), 504 (`timeout`), 503 (`not_configured`), 502 (`unavailable`); body `{ error, code }` with client-safe copy. 8s timeout. |
| `GET /api/media/tv/:id/season/:season?lang` | One season's episodes (number, title, air date) for the series detail; the client fetches a season only when it's picked. Series detail lists `seasons` (regular in order, specials last) | Public. `id` must be 1–10 digits and `season` 0–999 without leading zeros (400 otherwise, before TMDb is called) | Same codes and copy as title detail (404 for a season TMDb doesn't have). 8s timeout. |
| `/api/auth/*` | Register, login, current user, preferences, password change, account deletion | Register/login are public; `me`, `preferences`, `password` and `account` need a bearer JWT (HS256, `JWT_EXPIRES_IN`, default 7d). Bodies are parsed into known fields: email format, 8–72-character password, name ≤60, preferences `favoriteGenres`/`theme` only | 400 with a user-readable message; 401 for a wrong sign-in password or any invalid, expired, or orphaned session; 403 `wrong_password` for a wrong current password on `password`/`account`; 429 `rate_limited` with `Retry-After` and `retryAfterSeconds` after 5 failed password attempts per account or 20 per IP (per /64 block for IPv6; an IPv4-mapped address counts as its IPv4 address) in 15 minutes, before the password is checked; 409 `email_taken` for a duplicate email, which is why every well-formed sign-up (new or taken email) counts against 10 per IP (/64 for IPv6) an hour, after which register answers 429 `rate_limited` the same way; 503 `not_configured` when `JWT_SECRET` is unset |
| `/api/saved` | A user's favorites | Bearer JWT. Snapshots keep card fields only (https artwork); 500-item cap | 400 invalid snapshot, 409 list full, 401 session ended, 503 `not_configured` |
| `GET`/`PUT /api/collections` | A user's collections document | Bearer JWT. PUT replaces the whole document (last write wins); unknown collection ids, invalid snapshots, and assignments without a snapshot are dropped, not rejected. 1mb body limit | 400 non-object body, 401 session ended, 503 `not_configured` |
| Provider services (`server/src/services/*`) | Normalize provider data to the shared media shape | API keys from server env | Throw `ProviderError` with one of the codes above; a missing key is `not_configured`. |

Timeouts stop the API from waiting on a slow provider; the provider's underlying request is not aborted.

## Configuration
- Env var names: see `.env.example` (frontend) and `server/.env.example` (API).
- Mock vs. live mode (`VITE_USE_MOCK`, default `true`):
  - Mock mode uses the bundled dataset in `src/data/mockData.ts` and never calls the API for search, detail, or trending (the trending shelf uses a bundled list).
  - Live mode always calls the API. It never falls back to mock data when the backend is unreachable or a provider key is missing; instead the UI explains the failure and offers a retry where one can help.
- Local development: `npm run dev` (frontend, port 5173) and `cd server && npm run dev` (API, port 4000). The API's CORS allows `CORS_ORIGIN` only (default `http://localhost:5173`).
- Production: Vercel (Hobby). `vercel.json` builds `dist/`, rewrites `/api/*` to the `api/index.js` function (which exports `server/src/app.js`), and falls back to `index.html` for every other path. The frontend uses `VITE_API_BASE_URL=/api` (same origin) and `VITE_USE_MOCK=false`. Users are stored in Upstash Redis (free tier), because the function filesystem doesn't persist. The trending cache is per function instance, so a cold start refetches it. Vercel preview deployments serve as staging.
- PWA: `vite-plugin-pwa` (options in `src/pwa.ts`) emits `manifest.webmanifest` and a Workbox `sw.js` in production builds only; `src/main.tsx` registers it. The worker precaches the built shell and answers SPA navigations with `index.html`, except `/api/*` (denylisted); there is no runtime caching, so API responses, fonts, and artwork always hit the network. `autoUpdate` with `skipWaiting`/`clientsClaim` activates a new deploy's worker at once and reloads the page into it. `vercel.json` serves `sw.js` and the manifest with `Cache-Control: no-cache`. The PNG icons in `public/` are exports of the page icon `nova-stream.svg` (design-token colours): 192 and 512 px as drawn, the maskable 512 px with the mark at 72% on a full-bleed tile so it stays in the safe zone, and the 180 px apple-touch icon full-bleed. Re-export them whenever the SVG changes.

## Testing and CI
- Unit: Vitest for frontend utilities (`npx vitest run`); `node --test` for server modules (`cd server && npm test`, runs `src/**/*.node.js`).
- E2E: none configured; browser checks so far are ad hoc Playwright scripts, not committed.
- CI: none.
